# gutsy v0.4

**gutsy-0.8b v0.4** in two files from the same checkpoint, the **Q8_0** reference (the default in
the examples) and a new, smaller **Q4_K_M** GGUF, plus the **gutsy-inference 0.4.0** runtime.
v0.3 is still available: `hf download kouhxp/gutsy --revision v0.3`.

## Highlights

- JevBench public set: **169/231 (0.732)** with Q8_0 (v0.3: 167); easy 48/48, original 65/72.
- **Ambiguity:** on 48 held-out contrast pairs (same question, one state where the missing fact
  decides, one where the rules settle it), both answers right 0.417 (v0.3: 0.104). JevBench
  ambiguous 4/7 (v0.3: 0/7).
- **Reasoning:** held-out logic of a depth never trained on 0.842 (v0.3: 0.617), conditional
  probability 0.511 (0.305), comparative orderings 0.947 (0.840). BBH 0.481 (0.464).
- **Q4_K_M:** 505 MB instead of 775 MB, about 25-30% faster on CPU, the same evaluation-panel
  scores as Q8_0 (BBH 0.474, Financial PhraseBank 0.926, JudgeBench 0.563); JevBench 161/231.
- **Cleaner training data:** a shortcut audit now gates every build (no question template may be
  answerable from option count, length or position alone); v0.3's data had such shortcuts.

## Model

- About 105,000 training questions (v0.3: 90,000): 34,000 teacher scenarios (v0.3: 24,000), 687
  contrast pairs for ambiguity, and 6,900 code-generated reasoning puzzles with exact labels.
- Same method as v0.3: full fine-tune with frozen embeddings, cross-entropy + Brier loss,
  checkpoint chosen on a held-out development set. Same prompt format.
- Q4_K_M is quantized from the same checkpoint with llama.cpp's `llama-quantize` and ships its own
  calibration file (temperatures fitted the same way as for Q8_0).

## Runtime (gutsy-inference 0.4.0)

- `cache_tol` per model in `models.json`: keeps state caching on for low-bit quantizations
  (set to 0.02 for the Q4_K_M file in `models.example.json`). Default behavior is unchanged.
- `order_ensemble` per model (off by default): averages choice answers over several option
  orders. It helped BBH and JudgeBench by about 4 points in our tests but not JevBench, and it
  slows choice questions down, so it is off unless you turn it on.

## Regressions and known weak spots

- JudgeBench 0.539 with Q8_0, 0.563 with Q4_K_M (v0.3: 0.596); WinoGrande 0.620 / 0.629 (0.657).
- Calibration on JevBench's hard tier: 0.137 (v0.3: 0.078); on validation data unchanged.
- Still weak: date and number arithmetic (temporal_numeric 0.27; calendar-month arithmetic
  0.519, down from 0.683), new multi-step rulebooks (long_policy 0.32), world knowledge.

## Requirements

`gutsy-inference` 0.4.0 with `llama-cpp-python` >= 0.3.35, and `"reject_slot": true` in each v0.4
model's `models.json` entry (the included `models.example.json` already sets it, and `cache_tol`
for the Q4_K_M file). Files: `gutsy-0.8b-v04-q8_0.gguf` with `gutsy-0.8b-v04.calibration.json`
(model name `gutsy-0.8b-v04`, the default), and `gutsy-0.8b-v04-q4_k_m.gguf` with
`gutsy-0.8b-v04-q4_k_m.calibration.json` (model name `gutsy-0.8b-v04-q4`).
